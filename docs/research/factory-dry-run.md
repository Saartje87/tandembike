# Factory dry run on a throwaway repository (T1223)

Question: does the factory built in phase 9 (T1195) take an idea from Intake to Done in a repository with no process of its own, through the UI, with the Playbook and nothing else?

Date: 2026-11-09. Branch `ticket-1195-default-playbook` at `9e41b3f`, served by `npm run dev -- -p 3100` with `TANDEMBIKE_DATA_DIR=~/.tandembike-dryrun` and `TANDEMBIKE_MCP_URL=http://localhost:3100/api/mcp`. Data, database and run worktrees all lived in `~/.tandembike-dryrun`; the User's app on port 4747 and its `data/` were never touched. Claude Agent SDK 0.3.316, the Project's default model.

Answer in short: yes. Every Stage ran the Playbook's command from a blank Agent command, and the Epic went from an Intake idea to a merged PR and Done in about ten minutes of wall time and $1.06. The Merge gate held: nothing merged until Approve merge. Seven friction points are below, filed as Tickets.

## Method

- **Repository.** A new private GitHub repository, `Saartje87/tandembike-dry-run`, cloned at `/Users/niek/Projects/tandembike-dry-run`: a `greet` function, one `node:test` test, `npm test` and a GitHub Actions workflow running it, so the Merge run has checks to wait for. No `CLAUDE.md`, no `.claude/`, no skills.
- **Driver.** Headless Chrome through `playwright-core` and `docs/agents/browser-check/lib.mjs`, clicking what the User clicks. The Agent running the dry run played the User at each gate: it answered the Spec run's questions with the recommended options, approved the breakdown and clicked Approve merge. The User asked for this ("go ahead").
- **Seeding.** The Intake Ticket was filed through MCP (`file_tickets`) and the Cycle proposed with `create_cycle`; everything else went through the UI.
- **Measures.** Costs, durations and Run outcomes from the Stats page (`/stats`, "runs, last 30 days"), checked against each run's Claude Code log under `~/.claude/projects/`.

## Friction

1. **Agent mode is off for a new Project, even with a repository folder.** The Project needs Agent mode, and Parallel runs for the worktree, turned on in settings before the factory is hands-off. T1195 promised "the factory works hands-off from the first Start".
2. **New Projects offer `/mattpocock-skills:*` Skills chips.** The Agent commands now default to the Playbook, but the Skills chips still name a plugin a fresh repository's User may not have.
3. **Planning an Epic into a Cycle leaves its children in the Backlog.** `create_cycle` with the Epic planned only the Epic; its ready child showed as "Next" in the Backlog until planned separately.
4. **`file_tickets` takes one `originNumber` for the whole batch.** The Spec run filed the Epic and its child together, then had to set the Epic's Origin in a second call so the child did not get it too.
5. **The run's worktree is kept after the Ticket reaches Done from inside the run.** The Merge turn called `finish_work` while its Conversation was live; the clean worktree `~/.tandembike-dryrun/worktrees/1/c3`, whose commit is on `origin/main`, was still there afterwards. ADR 0033 says a clean worktree is removed when the Ticket reaches Done.
6. **The resumed Start run reads the merge skill from Tandembike's checkout.** `merge` is not model-invocable, so on the Approve merge reply the Start run read `playbook/skills/merge/SKILL.md` by its absolute path to follow it. It worked, but it rests on the model finding the plugin's folder; `implement` should carry the merge steps itself, or point at a model-invocable skill.
7. **Finished Triage and Spec runs read "Needs reply".** Both ended with a final report and nothing to answer, yet Stats count them under Needs reply with 0 Completed, so Stats cannot tell a finished Triage from one waiting on the User.
