# Activity is recorded inside the Tickets module

Every Tickets module function that changes a Ticket writes the Activity entry in the same transaction as the change, recording who is acting: `user` or `agent`, set by where the call came from, as for Comments in ADR 0006. The module takes the actor once, when it is created (`createTickets(db, actor)`), not on every call: the MCP route creates it as `agent` and Server Actions as `user`, and the parameter is required so no entry point can leave it out. It records only real changes and writes one entry per action, not one per field. We rejected building Activity from the live-update change channel (`changes.ts`, ADR 0005): it says only that something changed, not what or who, and it is not durable. Recording at the one write seam (ADR 0004) means a change cannot happen without its entry, whether it came from the UI or MCP.
