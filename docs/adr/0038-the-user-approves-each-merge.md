# The User approves each merge

Decided on 2026-11-09 (T1221, phase 9 of [`software-factory-2.md`](../roadmap/software-factory-2.md)). Amends [ADR 0019](0019-tandembike-starts-agent-runs.md) on who merges: a Start run no longer merges its own PR.

Amended by [ADR 0043](0043-auto-merge-lets-an-agent-merge-its-own-pr.md): with a Project's Auto-merge on, the run that opened the PR merges it, and the gate below applies when it is off or the run cannot meet the merge conditions. ADR 0043 also makes `finish_work` refuse unchecked acceptance criteria.

The roadmap made the User the **Merge gate**: a PR whose work is reviewed and whose checks are green waits for the User. Until now the Start run merged its own PR once CI was green, and the only button was **Merged**, for a PR the User had merged elsewhere. Nothing let the User approve a merge from Tandembike.

## Decision

- **A Start run hands off.** The Playbook's `implement` builds, checks, reviews its own diff and opens the PR with `open_pr` and `handOff: true`. It does not merge and does not call `finish_work`. The Ticket is in Review: a PR reference, no Claim, not Done.
- **Approve merge.** The drawer of a Ticket or Epic in Review shows **Approve merge** beside **Merged** and **Back to Todo**. Its Server Action calls the Conversations module, the only caller, so neither Autopilot nor an Agent can approve (ADR 0019). It is refused outside Review, without a PR reference, with a Claim, when the Ticket is Done and while a Conversation on it is running or waiting, and the refusal says why.
  - When the latest Start Conversation is open, it resumes it with a reply sent by the User: "Approved: merge T42 now by the Playbook's merge steps, then finish_work." Open means not closed and its run idle (it handed off) or interrupted (the server restarted); a stopped one takes no replies, and a working one is refused first. The run that wrote the code merges it with its context, by the merge steps in `implement`. The resume is a User reply, so the Start run limit does not check it (ADR 0031); a Merge Conversation is a new run and is checked.
  - Otherwise it starts a **Merge** Conversation with the Merge command, `/tandembike:merge T42` when blank. The `merge` skill checks out the PR branch in the Conversation's worktree, waits for the checks, merges the default branch in and pushes when the branch is behind or conflicts (rebasing only where force pushes are allowed, T1333), merges through the host CLI and calls `finish_work`. When it cannot, it comments why with `add_note` and stops without finishing, so the Ticket is in Action needed (ADR 0023).
- **A Merge always has a worktree**, even with Parallel runs off. It is detached at the default branch, and the `merge` skill checks out the PR branch there, which must not disturb the User's checkout. It counts against the Start run limit like a Start: one predicate, `holdsStartRunSlot`, says whether a Start or Merge holds a slot, for the limit and for Autopilot's free slots.
- **Spend.** A merge the User approves stays outside the Spend ceiling. A Merge Conversation is started by the User, so it is outside already. When Approve merge resumes a Conversation Autopilot started, the resumed run is recorded as a `merge` Run outcome of that Start Conversation, and its cost is subtracted from the Autopilot spend. The User's other replies on such a Conversation keep counting as before (ADR 0034).
- **Autopilot never starts or approves a Merge.** `start` refuses an Autopilot-started Merge. Autopilot's free slots count a working Merge.
- **Merged stays** for a PR the User merged by hand; both paths finish a Ticket.

Rejected: Tandembike calling `gh pr merge` itself (one host only, no conflict handling; ADR 0032's Playbook keeps the merge on the Agent's side), and the Start run asking in its Conversation whether to merge (the answer would be a free-text reply instead of one gate with a fixed meaning).

## Amendment: this repository keeps self-merge (2026-11-09, T1282)

Superseded by [ADR 0043](0043-auto-merge-lets-an-agent-merge-its-own-pr.md): this repository's self-merge is now the Tandembike Project's Auto-merge setting being on, which every run reads from `start_work`'s `merge`, not an instructions override of the Playbook. The note below is kept as history.

The decision above is the product default for every Project. Tandembike's own development deliberately does not follow it: a Start run on this repository merges its own PR with `gh pr merge --merge` once CI is green, its `review` is complete and every acceptance criterion is checked, then calls `finish_work`. It does not hand off with `handOff: true` for the User's Approve merge. The User decided this on 2026-11-09, triaging T1282 after the Cycle 48 retro: this codebase's runs already merged themselves by `docs/agents/start-run.md` (8 of 11 in Cycle 48), and the 3 that stopped to wait for a "merge" reply stalled their Tickets, so here the run's own `review` and CI are the gate. The override lives in this repository's instructions (`AGENTS.md` "Git workflow", "Playbook runs in this repository" in `docs/agents/start-run.md`), which the Playbook defers to; the Playbook's skills are unchanged. Approve merge and Merged still work here for a PR a run left open.
