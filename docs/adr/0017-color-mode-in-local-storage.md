# The Color mode choice lives in localStorage, applied by an inline script

The User picks Light, Dark or System, and the first paint must already be in that mode. A cookie would let the server render the right `data-color-mode`, but reading it in the root layout makes every page request-bound under Cache Components, so nothing is statically prerendered any more. So we keep the choice in this browser's `localStorage`. A small script in `<head>` puts it on `<html>` before the first paint, and the outermost `BlocksProvider` gets the same value, also while hydrating, so it never writes a different mode over it. The choice is per browser and does not follow the User to another one; storing it on the server or in the database was out of scope, since the app is local and has one User (ADR 0001). We rejected reading the cookie in the inline script, which works too, because a cookie the server never reads only adds a request header (T336).
