# Attachments are stored in SQLite and removed like Comments

An Attachment's bytes are a BLOB in the app's SQLite database, written in the same transaction as its Activity entry (ADR 0009), so an Attachment cannot exist without its entry, deleting a Ticket (ADR 0012) takes its Attachments with it, and the app's data stays one file to back up. We rejected files in a folder beside the database: they scale better, but a crash between file and row leaves strays, and deletion must clean up two places. A size cap per Attachment keeps the database manageable. Removing an Attachment destroys it, as for Comments (ADR 0006): it records whether the User or an Agent added it, the User can remove any, an Agent only one an Agent added, so an Agent's mistake cannot cost the User's files. An Agent may add an Attachment from a local file path that the server reads, so a screenshot never passes through the Agent's context; the server then reads any file it is given, which is acceptable only because the app is local and single-user (ADR 0001).
