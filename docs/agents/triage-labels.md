# Triage Labels

The skills speak in terms of five canonical triage state roles. Each is a native Ticket label of the same name. A Ticket carries exactly one state label at a time, so move it between states with one `update_ticket` call that names the old label in `removeLabels` and the new one in `addLabels`, for example `removeLabels: ["needs-triage"], addLabels: ["ready-for-agent"]`. Use `update_tickets` to move up to 50 Tickets the same way at once.

| Canonical role | Label | Meaning |
| --- | --- | --- |
| `needs-triage` | `needs-triage` | Maintainer needs to evaluate this Ticket |
| `needs-info` | `needs-info` | Waiting on the reporter for more information |
| `ready-for-agent` | `ready-for-agent` | Fully specified, ready for an agent |
| `ready-for-human` | `ready-for-human` | Requires human implementation |
| `wontfix` | `wontfix` | Will not be actioned |

Triage category roles are the labels `bug` and `enhancement`. Find Tickets in a role with `list_tickets` and its `labels` filter, for example `labels: ["ready-for-agent"]`.

Post triage notes as a comment with `add_comment`, not in the description. Start each with `> *This was generated by AI during triage.*`. Older Tickets may still have a `## Triage notes` section in the description; leave it in place.

Older Tickets may still carry `Triage category:` and `Triage state:` lines in their description. When you triage one, move those values to labels and delete the lines.

When completing a Ticket, remove its active triage state label (`needs-triage`, `needs-info`, `ready-for-agent`, or `ready-for-human`) in the same `update_ticket` call that sets its Status to `Done`. Preserve category labels such as `bug` and `enhancement`. Do not remove `wontfix` as part of this completion rule.

An Epic's Status follows its children and cannot be set, so that call never happens for one. Once an Epic's derived Status is `Done`, remove its state label with its own `update_ticket` call, giving `removeLabels` and no Status; its category labels and `wontfix` stay. See step 5 of "Working an Epic" in `issue-tracker.md`.
