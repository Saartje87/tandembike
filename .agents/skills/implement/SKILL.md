Implement the work described by the user in the spec or tickets. `docs/agents/start-run.md` owns one Ticket's workflow (Claims, Status, acceptance criteria, Done), `docs/agents/issue-tracker.md` the rest of the process, and `AGENTS.md` owns the git workflow; each step below points to the section it follows.

1. **Pick up the Ticket.** Read `docs/agents/start-run.md`. For a referenced Ticket, fetch it and state its title. If the reference is ambiguous, or several Tickets could match, ask which one. Claim it and move it to `In progress` by "Pick up" there, or for an Epic by "Working an Epic" in `docs/agents/issue-tracker.md`.
2. **Branch.** Work in a worktree of your own, so a parallel session in the same checkout cannot switch your branch. Already in a worktree Tandembike made for this run: create the branch there, as that section says. Otherwise create and enter one by "Worktrees for parallel runs" in `docs/agents/issue-tracker.md`, on the branch "Git workflow" in `AGENTS.md` names: `ticket-<number>-<slug>` off `main`, or the Epic's branch. Before each commit, check `git branch --show-current` names that branch; the Git guardrail refuses a commit on `main` or a detached HEAD.
3. **Build.** Call the Skill tool with "tdd" where possible, at pre-agreed seams. Run typechecking and single test files regularly, and `npm run check` once at the end; it must pass.
4. **Review.** Commit first: the review and the browser check both read committed work. For a change that touches code, call the Skill tool with "code-review" and fix what it finds. When it touches routing, navigation, a drawer or dialog, or a Server Action that navigates, also run a real-browser check by `docs/agents/browser-checks.md`: jsdom cannot run Next's routing, so those bugs pass every test. For a docs-only or copy-only change (the boundary `AGENTS.md` uses to exempt tests), check the change against each acceptance criterion inline instead. Check off each criterion as you verify it.
5. **Hand off.** Commit, push the branch, open the PR with the "pr" skill, and add its URL to the Ticket (or the Epic) as an External reference with `update_ticket` `addExternalReferences`. File the friction you hit by "Feedback as Tickets" in `docs/agents/start-run.md` here.
6. **Merge.** Wait for CI, then merge and complete the Ticket (or the Epic), or release the Claim when CI stays red, by "The Claim, through merge" in `docs/agents/start-run.md`. Then remove a worktree you made yourself by "Clean up" in "Worktrees for parallel runs". The step is done when the feedback is filed (or there was none), and the PR is merged and the Ticket is `Done`, or the PR is open with a comment on the Ticket saying why and the Claim is released.
